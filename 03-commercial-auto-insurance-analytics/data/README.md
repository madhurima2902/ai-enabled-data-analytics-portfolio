# Synthetic Dataset

The files in this directory are generated by `scripts/generate_synthetic_data.py` using a fixed random seed (`2902`).

The generator creates approximately the same scale of data as the original analysis represented by this portfolio project:

| Dataset | Rows |
|---|---:|
| quotes.csv | ~80,000 |
| policies.csv | ~32,000 |
| vehicles.csv | ~40,000 |
| premiums.csv | ~32,000 |
| claims.csv | ~6,500 |

The business relationships, reconciliation approach, and exception categories are modeled on the actual commercial-auto analytics work represented by this portfolio project. The published records themselves are synthetic and contain no original client data.

## Data-quality exceptions

The synthetic generator deliberately introduces representative data-quality problems across the quote, policy, vehicle, premium, and claims lifecycle, including:

- Duplicate quote identifiers
- Policies with missing quote keys
- Vehicles referencing nonexistent policies
- Policy/premium written-premium mismatches
- Claims referencing nonexistent policies
- Invalid policy effective/expiration date relationships
- Claims occurring outside valid policy terms
- Non-positive written premium
- Implausible vehicle model years

These defects are intended to produce **approximately 1,200 exceptions overall**, consistent with the rounded scale of issues identified in the original analysis. The portfolio does not depend on reproducing an exact exception count; the objective is to recreate the same types and approximate volume of data-quality problems for demonstration.

The generator validates the seeded defect categories before writing the output so that the profiling and reconciliation SQL can rediscover the intended issues.

Run from the project directory:

```bash
python scripts/generate_synthetic_data.py
```

This produces the full CSV dataset locally. Large generated CSVs can be kept out of source control while the generator, SQL checks, and documentation remain reproducible on GitHub.
